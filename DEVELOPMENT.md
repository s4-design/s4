# Разработка S4

Инструменты для работы над репозиторием: сборка дистрибутива, линтеры, тесты. Всё выполняется через скрипты `package.json` из корня репозитория.

Дистрибутив - папка `s4/`: она собирается из `src/` и копируется в проекты как есть, без правок. Продуктовая документация - в `README.md`, правила для AI-агентов - в `s4/AGENTS.md`.

## Сборка

Полная сборка - `pnpm s4`: выполняет пять шагов подряд. Каждый шаг доступен и отдельно:

| Скрипт | Команда | Назначение |
|---|---|---|
| `_s4-scss` | `pnpm _s4-scss` | Компилирует `src/scss/` в бандлы `s4/css/` (сжато, без sourcemap) |
| `_s4-js` | `pnpm _s4-js` | Минифицирует рантайм `src/js/s4.js` в `s4/js/s4.min.js` |
| `_s4-index` | `pnpm _s4-index` | Собирает словари контракта `utilities.json` и `variables.json` из уже скомпилированных файлов `s4/css/` |
| `_header-update` | `pnpm _header-update` | Обновляет лицензионные шапки файлов `s4/` (год, версия) |
| `check-docs` | `pnpm check-docs` | Сверяет документацию с контрактами: число утилит и таблицу элементов в `README.md` и `README.en.md` против `s4/contract/utilities.json` и `s4/contract/elements/` |

Порядок шагов обязателен: `_s4-index` читает результат `_s4-scss`, `check-docs` - результат `_s4-index`. Расхождение документации с контрактами останавливает сборку с кодом выхода 1.

## Линтеры

| Скрипт | Команда | Назначение |
|---|---|---|
| `lint` | `pnpm lint` | Оба линтера подряд (то же выполняет CI) |
| `lint:js` | `pnpm lint:js` | ESLint по `src/js/` - правила в `eslint.config.mjs` |
| `lint:css` | `pnpm lint:css` | Stylelint по `src/scss/` - правила в `.stylelintrc.json` (запрет физических свойств и дублей) |

## Тесты

Визуальные скриншотные тесты: Playwright сравнивает секции `test/index.html` с эталонами в двух пресетах. Команды и устройство - в `test/TEST.md`.

| Скрипт | Команда | Назначение |
|---|---|---|
| `test` | `pnpm test` | Сравнить с эталонами; расхождения кладутся в `test/__diff__/` |
| `test-update` | `pnpm test-update` | Перезаписать эталоны (после изменения стилей) |

## CI

`.github/workflows/ci.yml` на push в `master`/`dev_*` и PR в `master`: `pnpm lint` -> `pnpm s4` (сборка и автопроверка документации) -> артефакт `s4/` (только для `master`).
