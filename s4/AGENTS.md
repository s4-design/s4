# AGENTS.md - С4 (S4) для AI-агента

Эта папка - автономный дистрибутив интерфейсной "Системы 4" (С4). Всё содержимое этой папки предназначено ТОЛЬКО для AI-агентам.

## ЕДИНСТВЕННЫЙ АВТОРИТЕТ

Правила кодо-центричной вёрстки С4 заданы ТОЛЬКО в JSON-контракте:
- `contract/patterns.json` - точка входа: намерение UI → элемент С4.
- `contract/rules.json` - глобальные запреты с `id` (R1..R6) и рекомендации (G1..G4). R1..R6 обязательны к исполнению буквально; G* - рекомендации.
- `contract/utilities.json` - словарь utility-классов (базовые и существующие Ф2-производные). Перед использованием класса сверься со словарём: не все сочетания `property--modifier` существуют, класса нет - бери иную формулу/базовый класс. Валидатор `validate-s4.mjs` проверяет в любом случае - страховка от ошибок, в т.ч. ручной вёрстки.
- `contract/variables.json` - публичные переменные, кроме приватных `--size--*`.
- `contract/elements/<папка>/<элемент>.json` - спецификация элемента. Схема полей и когда их заполнять - в `contract/elements/template.json`. Для стандартных HTML-элементов (папка `modified`) контент-модель по умолчанию = стандарт HTML (WHATWG). Правило дельты общее для всех полей: заполняются ТОЛЬКО то, что С4 добавляет, сужает или что влияет на рендер по С4. Нет дельты - нет поля, отсутствие поля означает "по стандарту".

Термины дубликатов: "класс-дубликат" - класс `element--<имя>`, который даёт другому тегу вид и поведение элемента; в контракте он описан в `вариантах` как носители, куда его вешают. "Атрибут-дубликат" - атрибут, который сам по себе превращает носитель в этот элемент, класс не нужен: например `[type=submit]` или `[type=image]` делают элемент внешне кнопкой без `element--button`. Работает только там, где атрибут допустим по стандарту HTML.

Кастомный тег `<e-*>` - это НЕ flow-контент по стандарту HTML: неизвестный тег парсер считает inline, поэтому `<e-group>`, `<e-popover>`, `<e-body>` и прочие можно ставить внутрь любого фразового элемента, они не разрывают его структуру. То же для класса-дубликата на фразовом носителе: `<span class="element--badge">` внутри `p` допустим.

Ограничение касается только обычных (стандартных) блочных тегов. Элементы с контент-моделью Phrasing content по стандарту (WHATWG) не допускают блочных потомков: `p`, `span`, `h1-h6`, `button`, `label`, `code`, `cite`, `q`, `abbr`, `samp`, `mark`, `small`, `strong`, `sub`, `sup` и подобные. `<div>`, `<p>`, `<ul>`, `<details>` внутри такого родителя разрывают его, в том числе если стоят внутри `<e-*>` или class-дубликата. Тогда наполнять можно только inline-контентом.

Любой `.md` в этой папке вторичен. При расхождении `.md` с `contract/*.json` - истина в JSON. Не смягчай и не расширяй правила под задачу и под модель.

## ВНЕДРЕНИЕ В ПРОЕКТ

S4 - дополнение к любому проекту (чистый HTML или SPA на фреймворке). Папку `s4/` копируют в корень проекта рядом с `index.html`, как есть, без правок.

- Подключение: в `<head>` каждой страницы добавь `<script src="./s4/js/s4.min.js"></script>` и сразу `<script>S4()</script>`. `s4.min.js` сам подгружает нужные CSS (`config.css`, `*-utilities.css`) по `s4/dependency-map.json` в зависимости от устройства - отдельно CSS линковать не нужно.
- SPA (Svelte/Vue/React и т.п.): подключи `s4.min.js` один раз тегом `<script src="./s4/js/s4.min.js"></script>` и вызови `S4()` единожды при старте приложения, после монтирования корневого узла. Bundler и ES-модуль (`<script type="module">`) не поддерживаются: `s4.min.js` определяет базовый путь через `document.currentScript`, который при загрузке как модуль равен `null`. Повторный вызов безопасен (стили/скрипты грузятся однократно).
- Файлы в `s4/` - неизменяемый дистрибутив. Не редактируй их.
- Контракт и валидатор - в `s4/contract/`. Путь к валидатору из корня проекта: `s4/contract/validate-s4.mjs`.

## АЛГОРИТМ (строго)

1. Прочитай `contract/patterns.json`. Найди элемент под UI-намерение. Если элемента нет - семантический HTML + utility-классы (`G1`); НЕ выдумывай новый `<e-*>`.
2. Прочитай `contract/elements/<папка>/<элемент>.json`. Соблюдай `описание`, `атрибуты` (у атрибута проверь `обязательный`; у значения - `обязательный`, `варианты` для носителей класса-дубликата и `сочетания` для пар значений), `содержимое` с `дети` и `запрещено`. У ребёнка проверь `обязательный`, `примечание` и его собственных `дети`. В `modified` учитывай только дельту С4, остальное - стандарт HTML.
3. Сгенерируй разметку:
   - Элемент: `<e-{name}>` или `.element--{name}`, либо оба сразу (навесить `.element--{name}` на `<e-{name}>` для усиления веса селектора - не дубль, `G4`).
   - Утилиты: класс из `utilities.json` (базовый) или Ф2-производная `property--modifier` (`R3`). Одно свойство - один класс. Перед использованием проверь класс в `utilities.json`: готовых Ф2-производных меньше, чем всех сочетаний формулы; класса нет - подбери другой модификатор или базовый класс.
   - Псевдокласс в имени класса пиши БЕЗ экранирования: `class="background-color--transparent:hover"`. Экранированный слеш (`\:`) нужен только в CSS-селекторе, в разметке он ломает имя - валидатор отвергнет такой класс по R3, и браузер его не сматчит. В `utilities.json` классы тоже хранятся без слеша.
   - Поверхность предпочтительно через пресет/модификаторы; прямая surface-утилита допустима по запросу дизайна (`G3`).
   - `e-group`: направление распознаётся подстрокой `--row`/`--column` в имени класса. Посторонний класс с таким суффиксом (`product--column` и т.п.) на группе с `display--grid`/`display--inline-grid` молча перевернёт раскладку - не вешай такие классы на `e-group`.
4. Соблюдай `rules.json` R1..R6 буквально (G1..G4 - рекомендации):
   - `R1` - только логические свойства; `R2` - без `!important`; `R3` - один класс = одно свойство; `R4` - без физических сокращений в инлайн-стиле; `R5` - `--size--*` нигде в вёрстке; `R6` - в утилит-классах только `:hover` как состояние; `G1` - семантический HTML сначала; `G2` - Ф2 только при отличии от базового.
5. Запусти `node s4/contract/validate-s4.mjs <file>` (Windows: `node s4\contract\validate-s4.mjs <file>`). Нарушения - НЕ отправляй пользователю. Исправь и повтори, пока не будет `Валидация пройдена`.

## ТЕРМИНЫ

- **"кодо-центричная"** (не "кодо-ориентированная", не "кодо-центрированная").
- **"пресет"**, не "тема" и не "конфиг" - конфигурация интерфейса: атрибут `[preset]`, слой `@layer presets`, папки `_preset-*`.
- **"модификатор"** - часть класса после `--`.
- **"переменная"** - CSS-переменная `--*`. Слово "токен" запрещено: С4 кодо-центрична, источник правды - код и CSS-контракт.
- "С4" - в тексте (русское сокращение), "S4" - в коде и URL; `S4()` - только латинская S.
- Ступени шкалы: `--size--quantum` (не `--size--0_25`), `--size--0p5` (не `--size--0_5`).

## ЯЗЫК

Все ответы, комментарии, сообщения - на русском (английский только в именах классов/переменных/CSS). Многоточие - три точки `...`, не символ `…`. Кавычки - только прямые `"`/`'`.
