# AGENTS.md - С4 (S4) для AI-агента

Эта папка - автономный дистрибутив интерфейсной "Системы 4" (С4). Всё содержимое этой папки предназначено ТОЛЬКО для AI-агентам.

## ЕДИНСТВЕННЫЙ АВТОРИТЕТ

Правила кодо-центричной вёрстки С4 заданы ТОЛЬКО в JSON-контракте:
- `contract/patterns.json` - точка входа: намерение UI → элемент С4.
- `contract/rules.json` - глобальные запреты с `id` (R1..R6) и рекомендации (G1..G4). R1..R6 обязательны к исполнению буквально; G* - рекомендации.
- `contract/utilities.json` - словарь utility-классов. ТОЛЬКО для валидатора `validate-s4.mjs`; агент читает маски в `elements/*.json`, а не весь словарь.
- `contract/variables.json` - публичные переменные (переменные), кроме приватных `--size--*`.
- `contract/elements/<элемент>.json` - спецификация элемента: обязательные дети, допустимые/запрещённые утилиты, модификаторы, правило роли.

Любой `.md` в этой папке вторичен. При расхождении `.md` с `contract/*.json` - истина в JSON. Не смягчай и не расширяй правила под задачу и под модель.

## ВНЕДРЕНИЕ В ПРОЕКТ

S4 - дополнение к любому проекту (чистый HTML или SPA на фреймворке). Папку `s4/` копируют в корень проекта рядом с `index.html`, как есть, без правок.

- Подключение: в `<head>` каждой страницы добавь `<script src="./s4/js/s4.min.js"></script>` и сразу `<script>S4()</script>`. `s4.min.js` сам подгружает нужные CSS (`config.css`, `*-utilities.css`) по `s4/dependency-map.json` в зависимости от устройства - отдельно CSS линковать не нужно.
- SPA (React/Vue/Svelte и т.п.): подключи `s4.min.js` один раз (тег или bundler) и вызови `S4()` единожды при старте приложения, после монтирования корневого узла. Повторный вызов безопасен (стили/скрипты грузятся однократно).
- Файлы в `s4/` - неизменяемый дистрибутив. Не редактируй их.
- Контракт и валидатор - в `s4/contract/`. Путь к валидатору из корня проекта: `s4/contract/validate-s4.mjs`.

## АЛГОРИТМ (строго)

1. Прочитай `contract/patterns.json`. Найди элемент под UI-намерение. Если элемента нет - семантический HTML + utility-классы (`G1`); НЕ выдумывай новый `<e-*>`.
2. Прочитай `contract/elements/<папка>/<элемент>.json`. Соблюдай `обязательныеДети`, `допустимыеУтилиты`/`запрещённыеУтилиты`, `модификаторы`, `акцентРоль`.
3. Сгенерируй разметку:
   - Элемент: `<e-{name}>` или `.element--{name}`, либо оба сразу (навесить `.element--{name}` на `<e-{name}>` для усиления веса селектора - не дубль, `G4`).
   - Утилиты: класс из `utilities.json` (базовый) или Ф2-производная `property--modifier` (`R3`). Одно свойство - один класс.
   - Поверхность предпочтительно через пресет/модификаторы; прямая surface-утилита допустима по запросу дизайна (`G3`).
4. Соблюдай `rules.json` R1..R6 буквально (G1..G4 - рекомендации):
   - `R1` - только логические свойства; `R2` - без `!important`; `R4` - без физических сокращений в инлайн-стиле; `R5` - `--size--*` нигде в вёрстке; `R6` - только `:hover` как состояние; `G1` - семантический HTML сначала; `G2` - Ф2 только при отличии от базового.
5. Запусти `node s4/contract/validate-s4.mjs <file>` (Windows: `node s4\contract\validate-s4.mjs <file>`). Нарушения - НЕ отправляй пользователю. Исправь и повтори, пока не будет `Валидация пройдена`.

## ЯЗЫК

Все ответы, комментарии, сообщения - на русском (английский только в именах классов/переменных/CSS). Многоточие - три точки `...`, не символ `…`. Кавычки - только прямые `"`/`'`.
