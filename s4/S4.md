# Система 4 (С4) — кодо-центричная среда для построения интерфейсов

Интерфейс определяется комбинацией `{device × orientation × preset}`, а не каталогом компонентов. Ядро: трёхслойный каскад `@layer`, детерминированные формулы классов, размерная шкала `--size--*`. Пресеты - конфигурации интерфейса: метрики, цвета, типографика, анимации, поведение. Дизайн-система = С4 + пресет + компоненты и паттерны.

Этот файл - техническое описание для разработчиков и AI-агентов. Он описывает систему как она есть, включая архитектурные инварианты, формулы, соглашения и механику.

---

## Философия

С4 - **среда для построения дизайн-систем**, а не фреймворк с каталогом компонентов. Ядро даёт инструмент: каскад `@layer`, формулы классов, device-специфичную загрузку. Пресеты задают конфигурацию интерфейса - визуальную идентичность и поведение. Дизайн-система формируется из ядра С4, пресета и пользовательских компонентов и паттернов.

**Архитектурные инварианты С4:**

1. **Три слоя `@layer`** - elements, presets, utilities - с фиксированным порядком каскада.
2. **Детерминированные формулы классов** - любой класс парсится в CSS-правило без контекста.
3. **Размерная шкала `--size--*`** - 18 переменных (17 ступеней + служебная `--size--quantum`), линейно-параметрическая. Шаг = `--size--4 ÷ 4`.
4. **Device-специфичная загрузка** - каждый `{device × orientation}` имеет свой CSS-файл.
5. **Пресеты** - конфигурации интерфейса (метрики, цвета, типографика, анимации, поведение), собираемые отдельно для каждого устройства.

Default-пресеты (light/dark) - готовые конфигурации с EM-центричной моделью. Каждый пресет - самостоятельная конфигурация: light и dark могут совпадать в метриках сегодня, но ничто не мешает им различаться полностью. Кастомный пресет - другая конфигурация, на основе которой формируется новая дизайн-система.

## Архитектура

### Три слоя CSS

```
@layer elements, presets, utilities;
```

Каждый следующий слой доминирует над предыдущим:

1. **elements** - стилизация HTML-элементов и кастомных тегов через `var(--*)`. Ни одного жёсткого значения. Загружается один раз (`elements.css`).
2. **presets** - значения CSS-переменных, заданные в пресете (`@scope ([preset=light])`, `@scope ([preset=dark])`). Загружается для каждого устройства отдельно (`desktop/config.css`, `mobile/config.css`).
3. **utilities** - утилитарные классы (жёсткие значения + Формула 3 с переменными).

### Размерная шкала

Default-пресеты определяют **17 ступеней размерной шкалы** и служебную переменную `--size--quantum`. Размерная шкала является внутренним механизмом C4, а не публичным API.

**Инварианты шкалы:**
- `--size--4` - опорная ступень. В default-пресете она соответствует `1em`.
- Шаг вычисляется как `step = --size--4 / 4`.
- Остальные ступени вычисляются относительно `--size--4` и не переименовываются.
- Для изменения масштаба изменяется значение `--size--4`, а не структура шкалы.

```
step = --size--4 / 4
```

```
--size--quantum  = --size--4 / 16   (минимальный квант ¹⁄₁₆)
```

```
--size--0        = step × 0         (0)
--size--0p5      = step × 0.5
--size--1        = step × 1
--size--1p5      = step × 1.5
--size--2        = step × 2
--size--2p5      = step × 2.5
--size--3        = step × 3
--size--3p5      = step × 3.5
--size--4        = $base            (опорная)
--size--4p5      = step × 4.5
--size--5        = step × 5
--size--5p5      = step × 5.5
--size--6        = step × 6
--size--6p5      = step × 6.5
--size--7        = step × 7
--size--7p5      = step × 7.5
--size--8        = step × 8
```

Квантованная арифметика: `--size--2 + --size--3 = --size--5`. Индексы шкалы образуют линейную систему, поэтому операции над ступенями не приводят к появлению произвольных значений. Это позволяет AI и разработчикам использовать единую метрическую модель без нарушения сетки.

**`--size--*` - приватный строительный материал (не использовать напрямую в вёрстке).** Используется в двух местах:
1. **Определение семантических групп** - `--font-size--md: var(--size--4)`
2. **Стилизация элементов** - `--outline-width: var(--size--0p5)`

Ни одна `--size--*` не предназначена для прямого использования в вёрстке. Пользователь работает только с семантическими группами.

**Все метрики С4 — в `em`.** Размерная шкала (`--size--4 = 1em`) и все производные от неё (`--padding--md`, `--margin--l1`, `--font-size--md` и т.д.) заданы в `em`. Никаких `px` в пресетах нет. Это обеспечивает адаптивность: при изменении `font-size` на родителе масштабируются все дочерние отступы и размеры.

На их основе через `var()` выведены **семантические группы** - публичный API:

| Группа | Модификаторы | Пример |
|--------|-------------|--------|
| `--font-size--*` | s3, s2, s1, md, l1, l2, l3, l4 | `--font-size--md: var(--size--4)` |
| `--margin--*` | s3, s2, s1, md, l1, l2, l3, l4 | `--margin--md: var(--size--4)` |
| `--padding--*` | s3, s2, s1, md, l1, l2, l3, l4 | `--padding--md: var(--size--4)` |
| `--gap--*` | s3, s2, s1, md, l1, l2, l3, l4 | `--gap--md: var(--size--4)` |
| `--border-radius--*` | s3, s2, s1, md, l1, l2, l3, l4 | `--border-radius--md: var(--size--4)` |
| `--box-shadow--*` | s3, s2, s1, md, l1, l2, l3, l4 | `--box-shadow--md: var(--size--2)` |

Каждая группа - конвенция default-пресетов, а не архитектурное ограничение. Кастомный пресет может задать произвольные значения.

**Важно: модификаторы `s3…l4` — не глобальная шкала.** Каждое семантическое семейство (`--font-size--*`, `--margin--*`, `--padding--*`, `--gap--*`, `--border-radius--*`, `--box-shadow--*`) задаёт собственное значение модификатора; один и тот же `l2` даёт разный размер в разных семействах. Дефолтные значения (пресет light/dark, `--size--4 = 1em`, шаг `--size--4 / 4`):

| Модиф. | `--font-size--*` | `--margin--*` | `--padding--*` | `--gap--*` | `--border-radius--*` | `--box-shadow--*` |
|--------|------------------|---------------|----------------|------------|----------------------|---------------------|
| `s3` | `var(--size--2p5)` (0.625em) | `var(--size--1)` (0.25em) | `var(--size--1)` (0.25em) | `var(--size--1)` (0.25em) | `var(--size--1)` (0.25em) | `var(--size--quantum)` (0.0625em) |
| `s2` | `var(--size--3)` (0.75em) | `var(--size--2)` (0.5em) | `var(--size--2)` (0.5em) | `var(--size--2)` (0.5em) | `var(--size--2)` (0.5em) | `var(--size--0p5)` (0.125em) |
| `s1` | `var(--size--3p5)` (0.875em) | `var(--size--3)` (0.75em) | `var(--size--3)` (0.75em) | `var(--size--3)` (0.75em) | `var(--size--3)` (0.75em) | `var(--size--1)` (0.25em) |
| `md` | `var(--size--4)` (1em) | `var(--size--4)` (1em) | `var(--size--4)` (1em) | `var(--size--4)` (1em) | `var(--size--4)` (1em) | `var(--size--2)` (0.5em) |
| `l1` | `var(--size--4p5)` (1.125em) | `var(--size--5)` (1.25em) | `var(--size--5)` (1.25em) | `var(--size--5)` (1.25em) | `var(--size--5)` (1.25em) | `var(--size--3)` (0.75em) |
| `l2` | `var(--size--5)` (1.25em) | `var(--size--6)` (1.5em) | `var(--size--6)` (1.5em) | `var(--size--6)` (1.5em) | `var(--size--6)` (1.5em) | `var(--size--4)` (1em) |
| `l3` | `var(--size--5p5)` (1.375em) | `var(--size--7)` (1.75em) | `var(--size--7)` (1.75em) | `var(--size--7)` (1.75em) | `var(--size--7)` (1.75em) | `var(--size--5)` (1.25em) |
| `l4` | `var(--size--6)` (1.5em) | `var(--size--8)` (2em) | `var(--size--8)` (2em) | `var(--size--8)` (2em) | `var(--size--8)` (2em) | `var(--size--6)` (1.5em) |

Не вычисляй `em` сам — используй модификатор нужного семейства; для предсказания размера см. таблицу выше.

### Устройство и ориентация

Префикс класса или переменной = устройство + ориентация:

| Устройство | Ориентация |
|---|---|
| `d_` - десктоп | `l_` - альбомная |
| `t_` - планшет | `p_` - портретная |
| `m_` - мобильное | |

Префикс всегда двухсимвольный: `d_l_`, `m_p_`, `t_l_` и т.д.

CSS-переменные тоже могут быть адаптивными. Формула 3 строит цепочку fallback:

```css
var(--d_l_color, var(--color))
```

где первый аргумент - значение для конкретного `{device × orientation}`, второй - общее.

### Только логические свойства

С4 использует только логические CSS-свойства. Физические (`height`, `width`, `margin-top`, `padding-left` и т.д.) не применяются.

| Вместо физического | Используй логическое |
|---|---|
| `height` | `block-size` |
| `width` | `inline-size` |
| `min-height` | `min-block-size` |
| `min-width` | `min-inline-size` |
| `margin-top` / `margin-bottom` | `margin-block` / `margin-block-start` / `margin-block-end` |
| `margin-left` / `margin-right` | `margin-inline` / `margin-inline-start` / `margin-inline-end` |
| `padding-top` / `padding-bottom` | `padding-block` / `padding-block-start` / `padding-block-end` |
| `padding-left` / `padding-right` | `padding-inline` / `padding-inline-start` / `padding-inline-end` |
| `top` / `bottom` | `inset-block` / `inset-block-start` / `inset-block-end` |
| `left` / `right` | `inset-inline` / `inset-inline-start` / `inset-inline-end` |
| `border-top-*-radius` / `border-bottom-*-radius` | `border-start-start-radius` / `border-start-end-radius` / `border-end-start-radius` / `border-end-end-radius` |

Все классы Формул 1, 2 и 3 используют логические имена: `display--grid`, `d_l_margin-block--md`, `padding-inline` и т.д.

### Цвета

Акцентные цвета: `positive`, `negative`, `prime`, `second`, `success`, `danger`.

Каждый имеет четыре оттенка:

| Переменная | Описание |
|---|---|
| `--{x}` | Основной |
| `--{x}--light` | Светлый |
| `--{x}--dark` | Тёмный |
| `--{x}--mute` | Полупрозрачный (45%) |

Базовые: `--white`, `--black`, `--white--01`...`--white--09`, `--black--01`...`--black--09` (шаг 10% прозрачности).

### Что делает S4()

1. Устанавливает атрибут `[preset=light]` или `[preset=dark]` на `<html>` на основе `prefers-color-scheme` (если пресет не задан вручную). Если атрибут `[preset]` уже присутствует на `<html>` — значение сохраняется, и S4 больше не управляет пресетом.
2. Определяет устройство и ориентацию через `device-state` и добавляет на `<html>` классы текущего устройства и ориентации: `{device} {orientation}`. Например: `desktop landscape`, `mobile portrait`, `tablet landscape`.
3. Загружает `utilities.css` (один раз). Содержит классы **Формула 1** (единые, без префикса) и **Формула 3** (переменные). Эти классы всегда доступны независимо от устройства и ориентации.

4. Загружает `{device}/{orientation}-utilities.css` — только для текущего устройства и ориентации. Содержит классы **Формула 2** (адаптивные, с префиксом `{device}_{orientation}_`). Пример: на десктопе в альбомной ориентации грузится `desktop/landscape-utilities.css` — в нём классы `.d_l_display--flex`, `.d_l_color--black`. Если устройство или ориентация не совпадают — классы не загружены и не сработают.
5. Загружает `elements.css` (один раз). Содержит стили HTML-элементов только через `var(--*)` — ни одного жёсткого значения. Реальные значения подставляются из пресета (`{device}/config.css`), который загружен на шаге 4. Без пресета элементы не имеют видимого оформления.
6. Следит за изменением ориентации и за `prefers-color-scheme` в рантайме. Если пресет управляется автоматически, смена системной темы переключает атрибут `[preset]`.

## Утилитарные классы — 3 формулы

> Полный алфавитный перечень свойств с готовыми классами — см. [REFERENCE-UTILITIES.md](REFERENCE-UTILITIES.md).

### Формула 1 — единая

```
.{property}--{modifier}
```

Работает для всех устройств и ориентаций.

| Класс | CSS |
|---|---|
| `border--collapse` | `border-collapse: collapse` |
| `box-sizing--border-box` | `box-sizing: border-box` |


### Формула 2 — адаптивная

```
.{device}_{orientation}_{property}--{modifier}
```
Формула 2 работает с привязкой к устройству и ориентации.

| Класс | CSS | Устройство |  Ориентация |
|---|---|---|---|
| `d_l_display--flex` | `display: flex` | десктоп | альбомная | 
| `m_p_position--sticky` | `position: sticky` | мобильный | портретная |
| `t_l_align-content--space-around` | `align-content: space-around` | планшет | альбомная |

Формула 2 переопределяет "Формула 1" со схожим `{property}`.
Пример:
- color--prime — Формула 1, применяется везде
- t_p_color--second — Формула 2, переопределяет только на планшетах в портрете
```html
<div class="color--prime t_p_color--second">любой текст</div>
```

В xtra-слое (presets) модификатор - это имя CSS-переменной пресета, а не жёсткое значение:
```css
d_l_color--black { color: var(--black); }
d_l_font-size--md { font-size: var(--font-size--md); }
```
Любая переменная, объявленная в пресете, автоматически становится доступным модификатором. Например, если пресет задаёт `--brand-gradient: linear-gradient(...)`, то класс `d_l_background--brand-gradient` будет работать.

### Формула 3 — активатор + переменная

```
.{property}
```

Подключает CSS-свойство к цепочке переменных пресета:

```css
property: var(--{device}_{orientation}_{property}, var(--{property}));
```

| Класс | Содержимое |
|---|---|
| `.color` | `color: var(--d_l_color, var(--color))` |
| `.background-color` | `background-color: var(--d_l_background-color, var(--background-color))` |

Формула 3 делает свойство контекстно-зависимым. Один и тот же элемент может иметь разный `color` на десктопе и мобильном, в светлом и тёмном пресете, без изменения HTML. Значение определяется не CSS-правилом, а цепочкой переменных: сначала проверяется device-специфичное значение, затем общее.

---

### Правила работы AI с формулами

1. **Формула 1 — для всех устройств.** Если нужно применить CSS-свойство (например `display: none`), сначала ищешь готовый класс `.display--none` в `utilities.css`. Если класс существует — используешь его. Это как хардкорное значение в стилях, только переведённое в детерминированный класс.

2. **Формула 2 — для конкретного устройства.** Если нужно по-разному на разных устройствах (например `padding--md` на десктопе и `m_p_padding--s1` на мобильном в портрете), проверяешь в `{device}/{orientation}-utilities.css` наличие класса с префиксом. Если класс есть — используешь. `d_l_display--flex` сработает только на десктопе в альбоме, потому что этот класс лежит в `desktop/landscape-utilities.css`.

3. **Формула 3 + `style` — когда нет класса.** Если нужного класса нет ни в `utilities.css`, ни в `{orientation}-utilities.css` — ставишь класс-активатор (просто имя свойства, например `class="display"`) и задаёшь значение через `style="--display: none"`. Класс-активатор не задаёт значение, а только подключает CSS-переменную к свойству. Значение всегда задаётся в `style` как CSS-переменная.

4. **Проверка.** Любой класс перед использованием требует подтверждения. Если в `utilities.css` нет `display--none` — значит Формула 1 не подходит, используешь Формула 3 + `style`. То же для Формула 2: сначала проверить в `{device}/{orientation}-utilities.css`.

5. **Если класса-активатора Formula 3 нет.** Проверил `utilities.css` — класса-активатора `.свойство` не существует. Формулы 1, 2, 3 не подходят. Сообщи об этом пользователю: «Для свойства `X` нет класса-активатора в `utilities.css`. Нужно добавить класс `.X` через Formula 3 в `utilities.css`». Без подтверждения пользователя не используй инлайн-стиль и не создавай класс самовольно.

## Элементы

> Полный перечень элементов и их стилизации — см. [REFERENCE-ELEMENTS.md](REFERENCE-ELEMENTS.md).

HTML-элементы и кастомные теги С4 стилизуются через CSS-переменные. В `elements.css` нет жёстких значений - только `var(--*)`. Значения приходят из `config.css`.

Каждый кастомный элемент `<e-{name}>` имеет класс-дубликат `.element--{name}` для сред, где кастомные элементы недоступны (React, legacy). CSS-правило пишется через оба селектора:

```css
<e-{name}>,
.element--{name} {
    ...
}
```

| Тег | Класс-дубликат | Описание |
|---|---|---|
| | **Кастомные (created)** | |
| `<e-badge>` | `.element--badge` | Бейдж |
| `<e-icon>` | `.element--icon` | Иконка |
| `<e-popover>` | `.element--popover` | Поповер с телом |
| `<e-message>` | `.element--message` | Сообщение с header/body/footer |
| `<e-truncate>` | `.element--truncate` | Усечение текста |
| `<e-tag>` | `.element--tag` | Метка |
| `<e-group>` | `.element--group` | Группировка элементов |
| `<e-line>` | `.element--line` | Разделитель |
| | **HTML-теги (mutated)** | |
| `<a>` | - | Ссылка |
| `<abbr>` | - | Аббревиатура |
| `<blockquote>` | - | Цитата |
| `<body>` | - | Тело документа |
| `<button>` | `.element--button` | Кнопка |
| `<cite>` | - | Цитирование |
| `<code>` | - | Код |
| `<details>` | - | Раскрывающийся блок |
| `<dl>` | - | Список определений |
| `<fieldset>` | - | Группа полей формы |
| `<figure>` | - | Иллюстрация |
| `<h1>`–`<h6>` | `.element--h1` ... `.element--h6` | Заголовки |
| `<hr>` | - | Разделитель |
| `<input>` | - | Поле ввода |
| `<label>` | - | Подпись |
| `<menu>` | - | Меню |
| `<p>` | - | Абзац |
| `<select>` | - | Выбор |
| `<sub>` | `.element--sub` | Нижний индекс |
| `<sup>` | `.element--sup` | Верхний индекс |
| `<table>` | - | Таблица |
| `<textarea>` | - | Многострочное поле |

**Правила:**

1. **Один селектор на ноду.** Используй либо `<e-{name}>`, либо `<tag class="element--{name}">`. Никогда оба одновременно.
2. **Специфичность.** Класс `.element--name` (0,1,0,0) - наравне с утилитами С4. Кастомный тег `<e-name>` (0,0,1,0) - базовый слой. Любой утилитарный класс переопределяет стили элемента без `!important`.

3. **Сбросы не нужны.** С4 самостоятельно нормализует элементы через `elements.css` и пресет. Не добавляйте `margin: 0`, `box-sizing: border-box` и другие сбросы — все это уже есть.

Базовый HTML уже стилизован - классы не обязательны:

```html
<button>Нажать</button>
<input type="text" placeholder="Введите текст" />
<table>
    <tr><th>Имя</th><th>Значение</th></tr>
    <tr><td>Параметр</td><td>Результат</td></tr>
</table>
```

## Пресеты

Пресет С4 - **конфигурация интерфейса**, определяющая его визуальную идентичность и поведение. Пресет задаёт не только метрики (`--size--*`) и цвета, но и типографику (`--font-family`, `--font-weight`, `--line-height`, `--text-underline-offset`), анимации (`--transition-duration`, `--transition-timing-function`), поведение (`--overscroll-behavior`, `--word-break`, `--hyphens`, `--tab-size`), и любые другие CSS-переменные, необходимые проекту.

Пресет - слой дизайн-системы, не вся система. Дизайн-система = С4 (ядро: каскад, формулы, device-загрузка) + пресет (конфигурация интерфейса) + компоненты и паттерны.

Любая переменная, объявленная в пресете (`--{name}`), становится доступна как модификатор в xtra-утилитах Формулы 2. Например, если пресет задаёт `--brand-gradient: linear-gradient(...)`, то класс `d_l_background--brand-gradient` будет работать.

С4 определяет пресет через `prefers-color-scheme` и устанавливает атрибут `[preset]` на `<html>`. Если атрибут уже установлен до вызова `S4()` - значение сохраняется.

Пресеты изолированы через `@scope`:

```css
@scope ([preset=light]) { /* светлый пресет */ }
@scope ([preset=dark])  { /* тёмный пресет */ }
```

Каждый `@scope`-блок раскладывается на два селектора:

- `:scope { … }` — **токены** (метрики, цвета, типографика, анимации). Их читает генератор `s4-index.mjs` для словаря `variables.md`.
- `[preset] { … }` — **пресет-дефолты элементов** (`--position`, `--background-color`, `--color`, `--word-break`, `--tab-size`, `--font-size`, `--font-family`, `--font-weight`, `--line-height`, `--text-underline-offset`, `--overscroll-behavior`, `--hyphens`). Применяются к самому элементу пресета и обеспечивают изоляцию вложенных пресетов; в `variables.md` не попадают.

Пример содержимого (desktop, light):
```css
@scope ([preset=light]) {
  :scope {
    --transition-duration: .15s;
    --transition-timing-function: linear;
    /* …остальные токены: --size--*, --padding--*, --color-*, … */
  }
  [preset] {
    --position: relative;
    --background-color: var(--positive--light);
    --color: var(--negative);
    --tab-size: 4;
    --font-size: var(--font-size--md);
    --font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Oxygen, Ubuntu, Cantarell, "Open Sans";
    --font-weight: normal;
    --line-height: var(--size--6);
    --text-underline-offset: var(--size--quantum);
    --overscroll-behavior: none;
    --word-break: normal;
    --hyphens: auto;
  }
}
```

**Изоляция пресетов.** Пресет применяется к элементу с соответствующим атрибутом `[preset=...]`, независимо от вложенности. `<div preset="light">` может содержать `<div preset="dark">` - родительский пресет не влияет на дочерний и наоборот. Пресеты можно менять независимо от DOM-иерархии.

**Device-специфичность.** Каждый пресет собирается отдельно для каждого устройства (`desktop/config.css`, `mobile/config.css`, `tablet/config.css`). Значения `[preset=dark]` на десктопе могут отличаться от `[preset=dark]` на мобильном. Равенство между устройствами не гарантировано.

### Чтение конфигов перед вёрсткой

Прежде чем использовать любой класс Формула 1 (`padding--md`, `margin-block--s2`, `font-size--l1` и т.д.) — открой `{device}/config.css` для того устройства, под которое верстаешь. Убедись, что нужная переменная (`--padding--md`, `--margin--s2`) там есть, и посмотри её значение.

Пример: `desktop/config.css` задаёт `--padding--md: var(--size--4)`, что в default-пресете даёт `--size--4: 1em = 16px`. В кастомном пресете `--padding--md` может быть `2rem`. Без чтения config.css ты не узнаешь реального значения.

Если не знаешь, для какого устройства верстать — открой `desktop/config.css`, это baseline.

Важно: конфиги для разных устройств могут различаться. `--padding--md` на десктопе и на мобильном — не обязательно одно и то же число. Проверяй оба файла.

**Кастомный пресет - другая конфигурация интерфейса.** Установи `[preset="my-name"]` на `<html>` до вызова `S4()` и напиши CSS:

```css
@scope ([preset=my-name]) {
    :scope {
        --size--4: 1.25rem;
        --padding--md: 2rem;
        --color: oklch(0.2 0.02 260);
        --font-family: "IBM Plex Sans", system-ui;
        --transition-duration: 0.2s;
    }
}
```

**Иконографика, шрифты, прочие ресурсы** - вне ответственности С4. Пользователь дизайн-системы подключает их отдельно, так, как нужно его сборке.

**Для device-независимого стиля** используйте Формула 1 или явные значения в CSS. Пресеты влияют только на переменные — утилитарные классы Формула 1 и 2 не зависят от пресета.

Переключение пресета в рантайме отслеживается через `matchMedia('prefers-color-scheme')`. Если атрибут `[preset]` был явно задан на `<html>` до вызова `S4()`, автоматическое переключение отключается — системная тема не перебивает ручной выбор. Если атрибут не задан, `S4()` управляет им автоматически: при смене системной темы атрибут обновляется.

## AI-friendly

Архитектура С4 делает её необычно удобной для генеративных моделей:

### 1. Детерминированные формулы

Любой класс раскладывается по жёсткому паттерну:

```
d_l_display--flex    → display: flex
m_p_position--sticky → position: sticky
color                → var(--d_l_color, var(--color))
```

AI восстанавливает CSS из класса без контекста. Обратная задача - собрать класс из CSS - тоже однозначна.

### 2. Семантический HTML

С4 стилизует стандартные HTML-теги: `button`, `details`, `table`, `menu`, `input`, `select`, `a`, `h1`–`h6`. LLM обучены на миллиардах HTML-документов. `<button>Сохранить</button>` для них понятнее, чем `<PrimaryActionButton />`.

### 3. Параметрическое масштабирование

AI не нужно управлять каждым размером отдельно. В default-пресетах все метрики привязаны к `--size--*`. Изменение одного параметра пересчитывает весь интерфейс.

### 4. Минимум энтропии

Нет каталога компонентов с десятками пропсов. Есть комбинация `{элемент} + {модификатор}`. Пространство решений для AI - комбинаторика, а не перебор специализированных компонентов.

### 5. Предсказуемый каскад

```
elements → presets → utilities
```

Утилита всегда перебивает пресет, пресет - элемент. Никаких `!important`, никаких спекуляций. AI знает, какой слой победит, без вычисления специфичности.

## Публичный API (PUBLIC API)

Стабильные контракты С4. Изменение любого из них требует мажорного релиза.

**Три слоя `@layer`** — `elements, presets, utilities` с фиксированным порядком каскада.

**Формулы классов:**
- Формула 1 — `.{property}--{modifier}` (единая, для всех устройств)
- Формула 2 — `.{device}_{orientation}_{property}--{modifier}` (адаптивная)
- Формула 3 — `.{property}` (активатор + цепочка переменных)

**Элементы** — HTML-теги и кастомные `<e-*>` с классом-дубликатом `.element--*`. Стилизация только через `var(--*)`.

**Пресеты** — атрибут `[preset=*]`, изоляция через `@scope`, сборка отдельно для каждого устройства.

**JS-рантайм** — `S4()` и `dependency-map.json` (карта загрузки CSS по `{device × orientation}`).

**Семантические группы** — `--font-size--*`, `--margin--*`, `--padding--*`, `--gap--*`, `--border-radius--*`, `--box-shadow--*` с модификаторами `s3...l4`.

**Цвета** — акцентные `--positive`, `--negative`, `--prime`, `--second`, `--success`, `--danger` (с оттенками `--light`, `--dark`, `--mute`) и шкалы `--white--01...09`, `--black--01...09`.

## Внутренние механизмы (INTERNAL)

Могут меняться без мажорного релиза. Использовать только как строительный материал, не опираться в вёрстке.

**Размерная шкала `--size--*`** — приватный строительный материал. Используется для определения семантических групп и стилизации элементов, но не для прямого использования в вёрстке.

**SCSS-исходники** — `src/scss/_assets/`: слой использования `_elements/`, библиотека миксинов `_configs/_default/`, слои значений `_configs/_preset-light/` и `_configs/_preset-dark/`. Миксин `sizes()`.

**Device-префиксы** — `d_`, `t_`, `m_`, `l_`, `p_` и устройство-специфичные CSS-файлы (`desktop/`, `tablet/`, `mobile/`).

**`config.css`** — структура `@scope ([preset=*])`, порядок загрузки через JS-рантайм.

## MUST

Обязательные правила С4. Нарушение ломает архитектурные инварианты.

1. **Трёхслойный каскад `@layer`** — не нарушать порядок `elements → presets → utilities`.
2. **Детерминированные формулы** — один класс = одно свойство, без совмещения в одном селекторе.
3. **Модификатор = значению** — часть класса после `--` есть имя CSS-переменной пресета или жёсткое значение.
4. **Элементы только через `var(--*)`** — ни одного жёсткого значения в `elements.css`.
5. **Один селектор на ноду** — `<e-{name}>` либо `.element--{name}`, никогда оба одновременно.
6. **Только логические свойства** — `block-size`, `margin-inline`, `inset-block` и т.д.
7. **Формула 3 через цепочку переменных** — `property: var(--{device}_{orientation}_{property}, var(--{property}))`.
8. **Читать `{device}/config.css` перед вёрсткой** — реальные значения известны только из конфига.
9. **Изменение масштаба через `--size--4`** — структура шкалы не переименовывается.

## MUST NOT

Запреты С4.

1. **Не использовать `--size--*` напрямую в вёрстке** — только через семантические группы.
2. **Не использовать `!important`** — каскад решает всё без него.
3. **Не смешивать селекторы** — `<e-{name}>` и `.element--{name}` одновременно.
4. **Не добавлять CSS-сбросы** — `margin: 0`, `box-sizing: border-box` и прочее уже есть в С4.
5. **Не использовать физические свойства** — `height`, `width`, `margin-top`, `padding-left`, `left`, `right`, `top`, `bottom`.
6. **Не задавать жёсткие значения в `elements.css`** — только `var(--*)`.

## AI Generation Rules

Правила генерации классов для AI-агентов.

1. **Сначала Формула 1** — искать готовый класс `.{property}--{modifier}` в `utilities.css`. Класс существует — использовать его.
2. **Device-специфично — Формула 2** — класс с префиксом `{device}_{orientation}_` из `{device}/{orientation}-utilities.css`.
3. **Нет класса — Формула 3** — `class="{property}"` + `style="--{property}: value"`. Класс-активатор не задаёт значение, а подключает переменную к свойству.
4. **Проверка** — любой класс подтверждать по файлам перед использованием (`utilities.css`, `{device}/{orientation}-utilities.css`, `config.css`).
5. **Нет класса-активатора** — сообщить пользователю, не создавать класс самовольно и не использовать инлайн-стиль без подтверждения.
6. **Имя переменной = CSS-свойству** — без абстракций, прямое имя (`--inline-size`, `--transform`).
7. **Модификатор Формулы 2 = имени переменной пресета** — любая переменная пресета автоматически становится доступным модификатором.
8. **Один класс = одно свойство** — не комбинировать свойства в один класс.
9. **Семантический HTML** — `<button>`, `<table>`, `<menu>`, `<input>` вместо универсальных `<div>`.
10. **Читать `config.css`** — перед вёрсткой открыть `{device}/config.css` нужного устройства и убедиться в наличии и значении переменной.

## dependency-map.json

JS-рантайм грузит CSS на основе `dependency-map.json`. Дефолтная карта:

```json
{
    "desktop": {
        "landscape": [{ "desktop": "landscape" }],
        "portrait":  [{ "desktop": "portrait" }]
    },
    "tablet": {
        "landscape": [{ "tablet": "landscape" }],
        "portrait":  [{ "tablet": "portrait" }]
    },
    "mobile": {
        "landscape": [{ "mobile": "landscape" }],
        "portrait":  [{ "mobile": "portrait" }]
    }
}
```

Если файл не найден - используется встроенный fallback с той же структурой.

Пользователь может переопределить карту, чтобы добавить свои CSS-файлы в каскад или изменить приоритет загрузки для конкретного `{device × orientation}`.

Пример карты зависимостей (mobile-first):

```json
{
    "desktop": {
        "landscape": [
            {"desktop": "landscape"}
        ],
        "portrait": [
            {"desktop": "landscape"},
            {"desktop": "portrait"}
        ]
    },
    "tablet": {
        "landscape": [
            {"desktop": "landscape"},
            {"tablet": "landscape"}
        ],
        "portrait": [
            {"desktop": "landscape"},
            {"desktop": "portrait"},
            {"tablet": "landscape"},
            {"tablet": "portrait"}
        ]
    },
    "mobile": {
        "landscape": [
            {"desktop": "landscape"},
            {"mobile": "portrait"},
            {"mobile": "landscape"}
        ],
        "portrait": [
            {"desktop": "landscape"},
            {"desktop": "portrait"},
            {"mobile": "portrait"}
        ]
    }
}
```
